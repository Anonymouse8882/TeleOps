# TeleOps

Telegram 频道专业运营工具。基于 [Telethon](https://docs.telethon.dev/)，
把「从各种网站 / TG 频道采集信息 → 按规则加工 → 定时发布到自己的频道」这条链路做成可视化、可插拔的流水线。

```
信息源 ──▶ 采集器 ──▶ 工作流 ──▶ 调度器 ──▶ 输出端
 (源插件)   (过滤链)   (格式化链)  (定时/cron)  (频道群发)
```

一个频道可以被多个工作流挂载；一个工作流也可以同时发布到多个频道。

## 快速开始

```bash
python -m venv .venv
```

```bash
.venv\Scripts\pip install -r requirements.txt
```

```bash
copy config.example.yaml config.yaml
```

```bash
.venv\Scripts\python run.py
```

> Windows PowerShell 不支持 `&&` 连接命令，请用 `;` 或分开执行。
> 也可以直接双击 `start.bat`（带窗口）或 `start-background.vbs`（后台常驻，见下文）。

打开 <http://127.0.0.1:8800>，然后：

1. **设置** → 填写 `api_id` / `api_hash`（在 <https://my.telegram.org> 申请，所有账号共用这一套）
2. **账号** → 添加账号 → 手机号 + 验证码登录；已经在别处登录过的账号可以走「导入 session」页签，见下文
3. **频道管理** → 「从账号导入」一键拉取你能管理的频道，或手动添加
4. **工作流** → 新建，选信息源 → 配过滤 → 配格式化 → 勾目标频道 → 设间隔
5. 先点 **试运行** 看预览，确认没问题再 **启用**

自动拉起后台 → 直接出界面，和网页版是同一套东西。

```bash
cd desktop
```


```bash
npm start
```

打安装包（Windows 在 Windows 上打，Mac 在 Mac 上打）：


```bash
npm run build:mac
```

产物在 `desktop/dist/`：Windows 是安装版 `.exe` 和免安装 portable `.exe`，

开发模式（`npm start`）则直接复用仓库根目录，和 `python run.py` 完全等价。

## 获取登录验证码

账号列表里每个已登录的用户账号都有一个 **「获取验证码」** 按钮。

用途：这个号已经登录在 TeleOps 里，你要在**别的设备 / 程序**上登录它时，
Telegram 会把验证码作为消息发给账号自己（发信人是官方服务号 777000）——
TeleOps 直接替你读出来，不用去翻手机。

流程：**先点「获取验证码」开始监听，再去另一处触发登录。**

- 默认监听 3 分钟，弹窗里实时显示剩余秒数；收到就立刻显示，可一键复制
- 开始监听时会**回扫最近 10 分钟**的服务号消息，码要是已经到了就直接显示（标注「开监听前已收到」）
- 只认真正的验证码：登录提醒（`New login. Dear ...`）这类消息不会被误判
- **不挑语言**：Telegram 会按账号界面语言本地化这条消息，识别规则按「冒号 + 5~7 位数字」
  这个所有语言共有的骨架来匹配，中英西葡俄德法意日韩阿泰等 19 种文案实测都能抽出来
- 万一真没抽出来，弹窗底部会展开**服务号最近几条消息原文**，可以自己读
- 关闭弹窗（页脚按钮 / 标题栏 ✕ / 点遮罩）都会立即停止监听，不会在后台空转
- Bot 账号和未登录账号没有这个按钮——前者收不到，后者读不了

## 导入已有账号（.session）

不想再收一次验证码，可以把别处已经登录好的 session 直接拿过来用：
**账号 → + 添加账号 → 页签「② 导入已登录的 session」**
（页头的「导入 session」按钮是同一个弹窗的快捷入口）。支持两种来源：

| 来源 | 说明 |
| --- | --- |
| **.session 文件** | Telethon 生成的 SQLite session。选好文件会立刻做一次本地格式体检，不合格当场提示 |
| **Session String** | Telethon 的 `StringSession`（以 `1` 开头）。导入后会自动转存成本地 session 文件 |

导入时用的是**「设置」里的全局 api_id / api_hash**，弹窗里不用再填。
但要注意：session 的密钥绑定在生成它的那套 api 上，所以**这份 session 必须是用同一个 api_id 生成的**。
账号包里常附一个同名 `.json`（含 `app_id`），在弹窗里选上它会自动比对，
对不上会直接拦下并告诉你差在哪，不用等 Telegram 回一句看不懂的密钥无效。

点「验证并导入」时会**真的连一次 Telegram** 确认登录状态，然后才建账号：

- 成功 → 直接是「在线」状态，可以立刻用来采集和发布
- 失败 → 不会留下任何账号记录和文件，并给出具体原因（密钥失效 / 重复登录 / 已被登出 / 账号被封 / api 不匹配）

几个已知边界：

- **Pyrogram 的 .session 不通用**，格式不同，会被识别出来并明确提示，不会给一个看不懂的报错
- 同一份 session 在多处同时使用会触发 Telegram 的重复登录保护，导入时就会报错
- 导入后的 session 存在 `data/sessions/acc_<id>.session`，删除账号时一并清掉

## 设置

左侧「🔧 设置」里配置全局项：

| 项 | 说明 |
| --- | --- |
| **api_id / api_hash** | 在 <https://my.telegram.org> 申请，**所有账号共用一套**，账号页不再单独填 |
| 系统信息 | 只读，展示数据目录、插件目录、发送间隔等，来自 `config.yaml`，改动需重启 |

api_hash 保存后只回显掩码（如 `b184…e627`），明文不会再出现在任何接口响应里；
只想改 api_id 的话，api_hash 留空即可保持原值。

⚠️ **改 api_id 的代价**：账号的登录凭证（session）绑定在生成它的那个 api_id 上，
改动会让已登录的账号失效、需要重新登录或重新导入。保存前会提示有多少个账号受影响。
从旧版本升级时，会自动把第一个账号上的凭据提升为全局值，已登录的账号不受影响。

## 什么时候搬运（调度）

工作流一旦启用就会**一直按计划反复运行**，直到你手动停用或关掉服务——不是跑一次就结束。
工作流卡片上会实时显示「已运行 N 轮 / 下次 xx」，一眼能看出它还活着。

在工作流编辑器的「⑤ 什么时候搬运」里控制节奏：

| 设置 | 说明 | 例子 |
| --- | --- | --- |
| 运行频率 | 每隔一段时间 / Cron / 仅手动 | |
| 间隔 | 秒数或 `10m`、`2h`、`1d` | `30m` |
| **区间随机** | 填区间则每轮随机取一个间隔，避免固定节奏被识别 | `5m-15m` |
| Cron | 五段式，精确到点 | `30 9,18 * * *`（每天 9:30、18:30） |
| 额外随机抖动 | 在上面基础上再加 ±N 秒 | `60` |
| **每天允许搬运的时段** | 时段外的轮次自动跳过，不发内容；支持跨夜 | `09:00-23:00`、`22:00-06:00` |
| **只在这几天运行** | 勾选星期，全不勾＝每天 | 周一～周五 |
| **每天最多发布** | 当天发够就停，次日零点自动重置 | `20` |
| 时区 | 影响上面的时段和每日重置 | `Asia/Shanghai` |
| 每轮最多发布 | 控制单轮节奏，避免刷屏 | `5` |
| 发送间隔 | 同一轮内两条之间的停顿 | `3` 秒 |

被时间规则挡下的轮次不会写进运行记录（否则会刷屏），但会在卡片上显示一行原因，
例如「当前 02:13 不在活跃时段 09:00–23:00 内」。

## 让服务一直开着

后台服务本身要保持运行，工作流才会按时触发。三种方式：

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| 带窗口 | 双击 `start.bat` | 能看日志，关窗口即停 |
| **后台常驻** | 双击 `start-background.vbs` | 无窗口，关终端也不停；用 `stop.bat` 停止 |
| **开机自启** | 见下方 | 重启电脑后自动恢复 |

开机自启（任务计划程序，无需管理员）：

1. Win+R 运行 `taskschd.msc` → 右侧「创建基本任务」
2. 名称填 `TeleOps`，触发器选「计算机启动时」（或「当前用户登录时」）
3. 操作选「启动程序」，程序填 `wscript.exe`，参数填 `start-background.vbs` 的完整路径
4. 完成后在任务属性里勾上「不管用户是否登录都要运行」（可选）

也可以更简单：Win+R 运行 `shell:startup`，把 `start-background.vbs` 的快捷方式丢进去。

日志在 `data/teleops.log`，后台也能在「📜 日志」页实时看。

> 改动 `start.bat` / `stop.bat` / `start-background.vbs` 时请保持**纯 ASCII**：
> `cmd.exe` 和 `wscript.exe` 按系统 ANSI 代码页读这些文件，写中文会被解析成乱码
> 导致脚本静默失败。要显示中文提示，放进 `tools/stop.ps1` 那样带 BOM 的 `.ps1` 里。

### TG 频道搬运的三种模式

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| **增量** | 首轮只记游标不搬运，之后只搬新消息 | 实时跟发某个频道 |
| **从头开始** | 从第 1 条（或指定 `min_id`）按顺序往后补，进度持久化 | 冷启动填充新频道 |
| **随机** | 在 id 区间内随机取样，取过的记在池子里，用尽后自动重开一轮 | 老内容循环重发、养号 |

媒体处理：

- **复制** —— 复用源消息的 file reference，Telegram 服务端直传，不落盘、不耗本地带宽（最快）
- **下载** —— 存到本地再上传，可配合格式化插件二次加工，能去掉原始来源痕迹
- **忽略** —— 只要文字

### 多图消息（相册）

源消息带多张图时会整体搬过去，不会只搬一张：

- 抓取时如果相册被条数窗口切断，或随机模式只抽中其中一条，会自动**向外补齐**同一相册的其余成员（Telegram 相册最多 10 条且 id 连续，补齐开销很小）
- 说明文字跟随相册第一条，去重指纹也固定取首条 id，不会因为抓取顺序不同而重复发
- 输出端「多媒体合并为相册」关闭时，会**逐条单独发出**（内容不丢，只是变成多条消息）

### 多个源频道

「源频道」一栏可以填多个，**一行一个**（也支持逗号分隔）：

```
@channel_one
@channel_two
-1001234567890
t.me/channel_three
```

每个频道的进度游标**彼此独立**，删掉某一行不影响其他频道。多个源之间怎么取数由「多源策略」决定：

| 策略 | 行为 | 适用 |
| --- | --- | --- |
| **均分**（默认） | 每轮从每个频道各取一些，凑够单轮限额 | 想让各来源都有曝光 |
| **轮流** | 每轮只取一个频道，下轮换下一个 | 来源多、想保持每个频道内的顺序 |
| **合并** | 全部取来后按发布时间排序，取前 N 条 | 想严格按时间线搬 |

某个频道没权限或被删了，只会跳过它并记一条日志，不影响同一轮里的其他频道。

游标只在内容**真的发出去之后**才推进（`commit hook`），且按频道分别结算：
某个频道发送失败，只有它的游标不动，下一轮重试；被过滤规则全部筛掉的频道则正常跳过，不会原地打转。

## 写自己的插件

在 `plugins/sources|filters|formatters|sinks/` 下放一个 `.py`，几秒内自动热加载，**不用重启**：

```python
from teleops.core import Item, SourcePlugin, field

class MySource(SourcePlugin):
    name = "my_source"
    display_name = "我的采集器"
    config_schema = [field("url", "接口地址", "string", required=True)]

    async def fetch(self, ctx):
        data = await ctx.http_json(self.config["url"])
        return [Item(uid=f"my:{d['id']}", text=d["title"], url=d["link"]) for d in data]
```

`config_schema` 声明什么，后台就自动生成什么表单。完整说明见 [plugins/README.md](plugins/README.md)。

后台「插件管理」里还可以直接**在线查看/编辑源码**（保存即热重载，语法错误自动回滚）和**上传 .py 文件**。

## 命令行

```bash
python run.py --port 9000     # 换端口
python run.py --list          # 列出已加载插件
python run.py --run 3         # 只跑一次 3 号工作流后退出（可交给外部定时器）

```

## 配置

`config.yaml`（从 `config.example.yaml` 复制）：

| 项 | 说明 |
| --- | --- |
| `server.auth_token` | 后台访问口令，留空则不校验；也可用环境变量 `TELEOPS_TOKEN` |
| `runtime.send_interval` | 全局发送间隔，防限流 |
| `runtime.max_flood_wait` | 可接受的最大 FloodWait 秒数，超过则本轮放弃 |
| `storage.media_retention_days` | 下载媒体保留天数，0 表示用完即删 |
| `plugins.auto_reload` | 插件文件变动自动热重载 |

## 注意事项

- **账号安全**：搬运类操作请用小号，控制频率（`send_interval` 建议 ≥ 3 秒，配合 `jitter` 抖动）。
- **Bot 限制**：Bot 读不到未订阅频道的历史消息，搬运场景请用用户账号；Bot 适合只做发送端。
- **合规**：搬运他人内容前请确认你有相应授权，遵守 Telegram 服务条款和当地法律。
- 数据库是 SQLite，单机够用；`data/` 目录建议定期备份（含登录会话）。
